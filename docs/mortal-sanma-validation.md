# 三麻 Mortal v4 验证记录

本次适配针对 0.11.0 开发版本，验证日期为 2026-10-24。用户提供的 `mortal.pth` 是有效的三麻训练检查点，之前被四麻专用的导入限制拒绝，并非损坏的 ONNX。它应直接作为三麻 `.pth` 使用。

模型结构为 775×34 输入、44 个动作、256 通道、52 个残差块，包含 Mortal 主网络和 45 维组合价值/优势头。原文件 273,682,769 字节，SHA-256 为 `b7517a9b74351dc934b748bf4fc088669f0257aef51d9becd1a03ef84bab2b59`。权重不随源码分发。

验证结果：

- 真实 PyTorch 三麻网络与 Rust/Candle 使用相同的零值、稀疏和随机输入，三个样本的最大绝对误差分别为 `8.34e-7`、`6.26e-7`、`3.81e-6`，首选动作均一致。网络参考为 [Mateces/mortal-sanma](https://github.com/Mateces/mortal-sanma) 的 `mortal/model.py`；此项仅验证相同输入下的网络计算。
- 原文件在 ARM64 手机通过应用实际导入流程，识别为三麻 `mortal-pth`，加载、自检和激活成功。检查确认原有四麻模型及无人值守配置保留。
- 三麻机器人练习中，悬浮窗识别为 3 人和实验性 Mortal，并显示实时首选及备选切牌，未记录模型回退。
- Android 的小型 ONNX 图检查覆盖四麻/三麻、BOOL/FLOAT 合法动作 mask、三麻红五与拔北索引，以及人数和动作数交叉组合的拒绝。测试使用独立目录和偏好命名，避免改写用户模型。
- `mortal_sanma_smoke` 用精简模型验证完整 MJAI → 三麻观察编码 → 44 动作推理 → 合法推荐路径，没有回退到内置模型。

`tools/compact_mortal_checkpoint.py` 只保留推理所需网络和最小结构配置，去掉优化器等训练状态。该模型精简后为 91,381,693 字节，844 个推理张量逐项完全相同；精简文件 SHA-256 为 `03859386c2fc300c2a03b26613f0e8e62e70d5632336dd5a64e8ab726c5d92c8`。原文件不变。

仍有局面特征使用近似算法，尚未完成与上游整个观察编码的逐项对照。网络数值对照、合法动作检查和真机推荐显示，不等于推荐质量或长期对局表现已验证。导入模型不会启用无人值守，也不会把三麻模型应用于四麻。
