# 三麻 Mortal 推荐质量验证

2026-10-24 的结论：已修复影响推荐的协议和状态错误，但**完整推荐质量验证尚未通过，继续保持实验性**。本报告只适用于用户提供的 775 通道三麻 Mortal v4 检查点。

## 方法

同一份模型权重，分别接收应用和独立参考编码的同一局面，在电脑上本地推理，比较合法动作集合和贪心首选动作。参考采用 [Akagi 固定提交的 libriichi3p](https://github.com/shinkuan/Akagi/tree/91cc2993e4e3682248d33d73d93afe055040e700/mjai_bot/mortal3p) Windows/Python 3.12 模块，以及同提交的 `model.py`。参考 Bot 的回调提供实际观察和 mask，网络严格加载权重，未上传模型。

实际协议为 775×34 / 44，碰=38、杠=39、拔北=40，其他三麻分支需单独核对。参考 Bot 会把选杠牌的子任务放在主动作前面，验证工具区分两个批次，报告主动作。修复前动作编号会先解码为实际语义，避免数字相同而操作不同。

参考二进制和网络定义均校验固定哈希。精简模型 SHA-256 为 `03859386c2fc300c2a03b26613f0e8e62e70d5632336dd5a64e8ab726c5d92c8`，与原文件的 844 个推理张量相同。完整来源、校验值和失败案例见 [机器可读报告](validation/mortal-sanma-quality-20261024.json)。

## 结果

修复前基线是 `d53c247` 的生产编码。以下是**参考首选动作一致率，不是实战胜率或推荐正确率**。

| 测试组 | 修复前 | 修复后 | 修复后合法动作集合一致 |
| --- | --- | --- | --- |
| 开发集：120 个生成局面 + 9 个专项局面 | 69/129，53.5% | 120/129，93.0% | 129/129 |
| 留出集：新种子 20261026，300 个生成局面 + 9 个专项局面 | 未测 | 290/309，93.9% | 309/309 |
| 3 份公开三麻牌谱的无鸣牌前缀 | 40/70，57.1% | 69/70，98.6% | 70/70 |

专项覆盖拔北、碰、暗杠、加杠、立直、自家立直后摸牌、对手立直、荣和、自摸。留出集的 9 个专项案例与开发集重复。公开牌谱只取每局第一次鸣牌或拔北前的决策，隐藏对手手牌和摸牌。70 个局面来自 3 场牌谱，存在相关性，不能代表完整对局分布；是否出现在模型训练数据中未知。

## 已修复

- 三麻碰、杠、拔北动作编号及对应特征顺序错误。
- 三麻分数按四麻上限截断；宝牌持有量未按观察者座位旋转。
- 对手未知手牌占位符误计为宝牌，可见宝牌及鸣牌牌张计数错误。
- 回放未保留传入事件，导致立直接受状态和手切记录缺失；现在保存当前局事件，新局清空。
- 听牌/振听未使用摸牌前手牌，可杠窗口错误标为选杠牌阶段。
- 已打过牌后仍可能出现九种九牌候选。

78 项原生检查、13 项协议检查、真机 39 项控制器检查及四麻/三麻 ONNX/JNI 合约检查通过。11 个选定参考局面已固化为 Rust 回归数据，并加入 GitHub Actions。修正已构建并覆盖安装，保留用户模型和开关设置。

## 未通过的部分

三组测试中的完整观察向量均未逐项一致。主要缺口是三麻 SP 尾部 652–774 通道，包含期望值、进张表和按巡数的听牌/和牌概率等训练特征；另有部分河牌上下文、立直弃牌、同分排名和弃牌质量特征差异。

仅在电脑诊断中替换为参考 SP 尾部，留出集达到 **308/309**：原先 19 个差异均消失，同时出现 1 个新差异；公开片段达到 **70/70**。这支持 SP 是主要影响因素，也说明单独替换特征不能保证每局更接近参考。**这些参考 SP 特征尚未移植到手机，诊断数字不是应用实际一致率。**

尚未完成多杠选择、立直后具体弃牌等全部二阶段对照，也未做长局对战基准。本轮只能证明关键接入错误已修正，不能证明棋力或无人值守长期表现。应先完成 SP 和剩余特征对齐，再开展完整牌谱与成组对局评估。

## 复现

需要 Windows/Python 3.12、CPU PyTorch、NumPy、requests；读取 XML.zst 另需 zstandard。将上述固定提交的匹配模块保存为参考目录中的 `libriichi3p.pyd`，三麻网络定义保存为 `reference_model.py`。参考二进制和权重不分发。

```powershell
cargo build --release --manifest-path external/Akagi/native_bot/Cargo.toml --example mortal_observation_replay
python tools/validate_mortal_sanma.py --reference-dir <参考目录> --checkpoint <模型.pth> --replay-exe <mortal_observation_replay.exe> --output <结果目录> --samples 300 --seed 20261026 --diagnose-sp
```

公开牌谱的固定来源和校验值见机器报告。下载后运行：

```powershell
python tools/tenhou_sanma_prefix_cases.py <XML.zst目录> <cases.json>
python tools/validate_mortal_sanma.py --reference-dir <参考目录> --checkpoint <模型.pth> --replay-exe <mortal_observation_replay.exe> --output <结果目录> --cases <cases.json> --diagnose-sp
```
