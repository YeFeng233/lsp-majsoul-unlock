# 0.10.0（开发构建）

本次选择性整合 linyuanjianying 分支 v0.9.3 / v0.9.4 及其后续部分修正，保留本仓库的更新来源、安装签名和无人值守操作保护。

- 调整吃、碰操作的客户端界面读取：只检查当前操作所需的界面，避免无关界面异常阻断操作。增加分阶段诊断日志，同一指令的重复诊断会去重。
- 吃碰目标优先核对 Hook 捕获的最近舍牌与出牌座位；客户端缓存短暂落后时仍须通过协议、手牌、操作组合和步骤校验。目标或来源不匹配时继续拒绝执行。
- 保留每次 2–5 秒随机延迟、手动操作立即关闭、过期指令撤销和不盲目重试的行为。
- 修正真机长测发现的庄家起手卡住：游戏会先排序完整的 14 张起手牌，界面“最后一张”可能不同于协议首摸。仅在完整协议确认的庄家首张舍牌中，由原始客户端确定摸切标记，继续严格核对牌名、赤牌、完整手牌、回合和来源；第一张舍牌后恢复普通摸切校验。
- 新增实验性四麻 Mortal v4 模型导入，支持匹配结构的 ONNX、PTH 和 PT；单文件上限保持 128 MiB，能够识别误命名为 ONNX 的 PyTorch ZIP。模型不上传，仓库不附带 Mortal 权重。
- ONNX 支持布尔及浮点合法动作 mask，使用当前实际合法动作；兼容非法动作输出负无穷的图。继续验证 Akagi 模型元数据，拒绝不支持的三麻 Mortal 和旧版网络。
- 修正移植代码的副露后向听参数、万子宝牌映射、振听等待牌计算和推荐排序后的概率索引；补充加载结构与激活检查。
- Mortal 暂时只提供手动建议，启用后会关闭无人值守。部分特征仍是近似实现，尚未完成与上游的完整一致性验证，自检通过不代表模型建议质量已经验证。
- 补充来源说明、Mortal 派生组件的 AGPL-3.0 许可，以及应用内的开源许可入口。

构建检查包含 Lua 操作保护、Rust 特征及状态恢复回归、Android 控制器与 ONNX 导入测试，以及两种 APK 的 ABI、签名与对齐检查。

Android 17 ARM64 真机已验证新版 Hook 连接、真实 `four.onnx` 的 PyTorch ZIP 识别、加载推理自检和实时手动建议；三麻 Mortal 文件被拒绝，实验性模型禁止无人值守。内置策略在机器人练习中完成自动切牌、跳过、立直、两次碰牌及结算继续，并取得服务器确认。Mortal 的完整上游一致性与建议质量仍未验证，正式 Release 发布需另行确认。
